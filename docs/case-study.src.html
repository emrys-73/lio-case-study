Reading and writing

  • Writes are strict. Unknown keys, empty keywords or a group that doesn't exist: rejected (422).
  • Reads are tolerant. An unknown key or a dead rule is skipped and logged. The page never breaks.
  • Saves merge. Saving required fields keeps the rules.
  • One reader. Every part of the code calls load_settings(org).
  • Admins only. The server stamps who and when on each rule.

How a rule hits

  • Checked line by line, top of the list first. First hit wins.
  • max_amount set: only lines at or under that total.
  • Lines hit different rules: the highest-value line decides. Flagged.
  • A hit locks the group. The classifier never runs.
  • A buyer or admin can override. Logged with the rule ID.

Keyword matching, German and English

  • A rule lists its words in both languages. No translation step.
  • Both sides are cleaned the same way: lower case, ä ö ü ß become ae oe ue ss, hyphens and punctuation become spaces.
  • A one-word keyword hits a word that starts or ends with it. So toner hits "Tonerkartusche" and "Druckertoner".
  • A keyword of several words must appear in that order. Each word may run longer, so cable tie hits "cable ties".
  • Keywords under 4 letters must match the whole word.
  • Near misses are tests: "Kabeltrommel", "printer" and "ERP licence" must hit nothing.
  • More languages later: add keywords, or a new cleaning step. The rule shape stays.

Shared search

Eval first One function for two lists.

  • Job: text in, a short list out. Groups for Problem 3, Acme's articles for Problem 2.
  • Goal: the right answer is somewhere in the list. Picking the one is the next step's job.
  • Groups: 2,000 rows are 380 real names with size and tier copies. Search the 380.
  • Articles: 1,920, only the signed-in company's.
  • Catch: quotes are German, the lists are English. Plain word match will miss.
OptionHowGoodWeak
AWord matchNo key, no cost, same answer every runGerman to English
BEmbeddings, made once, kept in memoryHandles German to EnglishNeeds a key to build
CNo search: model picks a category, then a groupNo search codeA wrong category can't be undone. No use for articles.
  • Our pick: B with A merged in. A is also the fallback with no key.
  • Decided by numbers: about 30 labelled lines, score "right answer in the top 15" for A, B and C.
  • Skipping the classifier when the search is very sure: only if the eval shows the top hit is reliably right.

Our pick

How it's worked out

  • Engine in backend/evals/cost/: prices.json, scenarios.json, engine.py, report.py. 21 tests, no network.
  • Every price names its source and the day it was checked. gpt-4o-mini is $0.15 in and $0.60 out per million tokens.
  • Measured rows read the eval logs. Estimated rows start from a measured run and list their changes: drop the group list, skip pictures, swap the model, add a call.
  • Picture tokens follow OpenAI's vision guide: 512 px tiles for gpt-4o-mini, 32 px patches for gpt-4.1-mini.
  • Re-run after any eval: docker compose exec backend python -m evals.cost.report. Each run is saved in evals/cost/results/.
