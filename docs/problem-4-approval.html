Acme said

"Anything below €2,000 shouldn't need approval at all."

Do we have tests?

Built 10 Nov

  • 50 backend tests in tests/test_approval.py: the rule, the setting, create, edit and the seed.
  • 4 frontend tests for the "Auto" label. Full backend suite: 324 passed.

How it works today

  • Every new request starts as pending.
  • A buyer or admin sets it to approved or rejected. Once only.
  • The total is total_cost on the request.
  • Gap we found: any member, even a requester, can set the status to closed. Even before approval. Decided 10 Nov: its own fix, not part of this bonus.

Tests to write first

All pass

  • €1,999.99 is approved on create.
  • €2,000.00 stays pending.
  • No total stays pending.
  • The total is added up from the lines in code. The total the form sends is ignored.
  • Lines that don't add up to the printed total: never auto-approved.
  • Auto-approval writes "auto-approved" to the activity log.
  • Editing an approved request above €2,000 sends it back to pending.
  • Another company without a limit keeps today's behaviour.

Decisions

Decided 10 Nov

  • Total added up in code. The limit is checked against it, never the total the form sends.
  • Net, not gross. €2,000 means the total before VAT. Why: the request total is the net cost everywhere else (Problem 1), and typed requests have no VAT to add.
  • Strictly below. €1,999.99 is approved on its own. €2,000.00 still needs a buyer. Why: Acme said "below".
  • A company setting, no screen yet. approval_limit in the company settings, next to the rules. Acme gets 2000. No limit set keeps today's behaviour.
  • The closing gap is its own fix. Not part of this bonus. Logged under Later.
  • Edits follow the same rule as create. A pending request edited below €2,000 approves on save.
  • A buyer's no stays a no. Editing never overturns a rejection.
  • A buyer's yes resets only if the total rises. Same or lower stays approved. An auto-approved request edited to €2,000 or more goes back to pending.
  • Both are recorded. Auto-approval sets the approval time and logs auto_approved. Going back to pending clears the time and logs approval_reset with the old and new totals.
  • The strict totals check blocks it. Lines against the printed net, as saved today. A misread net waits for a buyer. Safe side.

Later

  • An admin screen to set the limit.
  • Use the form's gross check at save too, so correct quotes stop waiting for a buyer.
  • Clearing the limit through the API drops the key, so the seed puts €2,000 back on the next start. Store an empty limit instead.
  • Stop requesters closing a request, and stop anyone closing one before approval.
  • Splitting one order into small ones to stay under the limit. Not solved. Flag it to Acme.
