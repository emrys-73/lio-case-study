Contract

  • Request responses (list, detail) add approval: { decision: "auto_approved" | "needs_buyer", decided_by: "system" | "user", decided_at: datetime | null, net_total: decimal string, limit: decimal string | null, reasons: Reason[] }.
  • Reason: { code: string, message: string, line_id: uuid | null }. Codes: under_limit, over_limit, no_limit, no_total, totals_mismatch, group_rule_overridden, group_low_confidence, cheaper_catalog_ignored, edited_over_limit. The last three group codes are proposals.
  • Statuses stay as they are: approval_status is pending | approved | rejected, status is open | in_progress | closed. Auto-approval sets approved, approved_by: null, approval.decided_by: "system".
  • Before submit: POST /requests/approval-check takes the draft (lines, commodity group, flags) and returns the same approval object without saving. Save recomputes it; the preview is a hint only.
  • Setting: organizations.settings.approval = { auto_approve_below: number | null, always_to_buyer: { group_rule_overridden: bool, group_low_confidence: bool, cheaper_catalog_ignored: bool } }. Net EUR, strictly below. null means no limit. Totals mismatch is not a setting, always on. Read and PATCH (merge) through the existing org settings endpoint, admin only.
  • Activity: one RequestActivity on create or edit, action: "auto_approved" | "sent_to_buyer", detail: { net_total, limit, reasons }.
