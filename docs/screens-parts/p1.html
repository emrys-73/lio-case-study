Contract

  • Extraction reply. Every field may be null, it never errors on a missing value.
  • Totals are added up by the backend in code, never by the model. Alternatives are never in linesNet.
  • department comes from the user profile, not from this reply.
{
  "title": string | null,
  "vendorName": string | null,
  "vatId": string | null,
  "missingFields": ("title" | "vendorName" | "vatId")[],
  "currency": "EUR",
  "orderLines": [{
    "position": string | null,
    "description": string,
    "amount": number,
    "unit": string | null,
    "unitPrice": number,
    "totalPrice": number
  }],
  "alternatives": [{
    "position": string,
    "replaces": string | null,
    "description": string,
    "amount": number,
    "unit": string | null,
    "unitPrice": number,
    "totalPrice": number
  }],
  "totals": {
    "printedNet": number | null,
    "linesNet": number,
    "differs": boolean
  }
}
  • alternatives come back on their own, only to show "not included". They are never sent back.
  • On Create Request, the frontend adds to today's request body: totalCheck: { printedNet: number | null, linesNet: number }.
  • missingFields never block submit. Only the organisation's required_fields do.
  • Backend rule: if printedNet and linesNet differ, the request never auto-approves.
  • Later: pickedAlternatives, totalCheck acknowledged + reason.
