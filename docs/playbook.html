FDE Playbook

Fixing Acme's procurement in 5 hours

The goal

  • Acme sent 3 complaints and 1 bonus ask.
  • Fix what matters most first.
  • Prove each fix with numbers.
  • Hand off one pull request to main.
  • Customer: Acme Corp
  • Timebox: 5 hours
  • Stack: FastAPI, Next.js, Postgres
  • Screens: App Map ↗

Acme's asks, and our move

1

PDF extraction isn't reliable

Fields come out wrong or empty. Some uploads crash.

Our move

  • Label the 5 quotes by hand. That's the answer key.
  • Build an eval. Score every field. Count crashes.
  • Record the score. Fix. Run it again.
2

It doesn't use the prices we negotiated

People buy off-catalog. Suggest our catalog articles instead.

Our move

  • Write tests first: request text in, right article out.
  • Only search Acme's own catalog.
  • Show the negotiated price in the form.
3

Categories don't match Acme's books

Cable ties: Electrical Engineering. Toner: IT Hardware. Small software: Office Supplies.

Our move

  • Eval the current categoriser on these cases.
  • Add Acme rules that always beat the model.
  • Keep rules in Acme's settings. No hardcoding.
★

Bonus: no approval under €2,000

Buyers waste time signing off small requests.

Our move

  • Write tests first for €1,999, €2,000 and €2,001.
  • Make the limit an admin setting.
  • Log "auto-approved" in the activity trail.

Optional. Only if time is left.

How we build

Prove it

  • Evals live in the repo.
  • The PR shows before and after.
  • Tests before code.

Per customer

  • Acme's quirks are Acme's settings.
  • Companies stay isolated.
  • Rules beat the model.

Explain it

  • Log every automatic decision.
  • Show where a suggestion came from.

Ask Acme

  • What counts as "small" software?
  • Is €2,000 net or gross?
  • Should suggestions nudge or block?

How we work with AI

  • Agree the approach before any code.
  • AI changes start with an eval and a score.
  • Other changes start with failing tests.
  • Each doc builds on the last. No repeats.
  • Short sentences. Bullets.
