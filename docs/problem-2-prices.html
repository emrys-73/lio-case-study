PROBLEM 2

Negotiated Prices

Suggest Acme's catalog articles when a request is made

All problems ↗Playbook ↗App Map ↗Problem 1 ↗Problem 2Screens ↗Problem 3 ↗Bonus ↗

Acme said

"When someone creates a request, I want the system to suggest the matching articles we already have on catalog, so we actually use those agreements."

Do we have tests?

Not for this

  • One test checks the article list is per company, paged and searchable.
  • Nothing matches a request to an article. The feature doesn't exist.

What exists today

  • Article table, per company: number, supplier, description, negotiated unit_price, unit, pack quantity.
  • 1,920 articles in the seed file.
  • GET /articles?search=: plain text match on description or number.
  • An Articles screen to browse them.
  • Missing: any link between an order line and an article.
{'article_number': 'LIN-00862', 'supplier_name': 'Lindqvist Supply B.V.',
 'description': 'Toner cartridge black, high-yield',
 'unit_price': 186.0, 'unit': 'piece', 'quantity': 10.0}

Tests to write first

Needs your OK

  • A line "Toner schwarz" suggests the Lindqvist black toner.
  • Only Acme's articles come back. Never another company's.
  • No good match returns nothing, not a random article.
  • The suggestion shows the negotiated price and the supplier.
  • German and English wording both match.
  • The picked article lands in the activity log, with its number and price.

Decisions before any code

  • How to match: the same search that shortlists commodity groups. Word match, embeddings or both, picked by an eval: Shared search ↗.
  • When: after PDF extraction, while typing a line, or both?
  • Nudge or block: show a hint, or require a reason to go off-catalog?
  • Store the link (decided 10 Nov): the picked article is logged in the activity log JSON. No schema change. A column on the order line is for later.
